## Remaining findings, highest severity first — separate focused tasks

1. **High — pre-review scores still escape through other student consumers (code-confirmed).** `quizService.getStudentAnalytics`, `analyticsService.getDashboardStats`, and the teacher `submitAllAnswers` response expose completed scores without the result page's teacher-review gate. History's teacher-reviewed predicate also needs completed-status consistency for legacy early-grade data. **Task:** centralize the existing release decision, apply it to student summaries/history/analytics/submit DTOs without browser scoring. **Accept:** an owned unreviewed attempt stays pending in every response; reviewed 1/3/33% agrees everywhere; foreign attempt denied, active keys never returned. Do not change the teacher release policy.
2. **High — required exam settings can still be silently dropped (code-confirmed).** `quizService.createQuiz/updateQuiz` retain missing-column fallback retries for camera/scope/violation settings; `isMissingColumnError` treats any 42703 too broadly. **Task:** replace these fallbacks with precise actionable schema errors and keep entered teacher input. **Accept:** missing each required column prevents a misleading successful save; applied schema round-trips course scope, monitoring choice and violation threshold; unrelated DB errors are not mislabeled.
3. **High — browser integrity-event retries are not durable (code-confirmed).** `QuizTakePage` retries a report three times, then only shows an error; refresh discards the unsent browser list and there is no explicit retry queue. The message implying a later connection will save it is too strong. **Task:** add an attempt-scoped stable-ID queue with explicit retry/error state, ownership-safe recovery and bounded retry/backoff. **Accept:** offline beyond three attempts → reload → reconnect preserves one event, two distinct events stay two, and a submit/report race preserves saved score. Test fake events, not real misconduct.
4. **High release gate — database/concurrency and payment sandbox not verified.** Files 021/023/026–028 and mocked RPC tests do not prove deployed uniqueness, grant/RLS state, transaction rollback, simultaneous final-seat/start/submit/report, or a real payment verification response. **Task:** run the isolated staging runbook with two real DB connections and sandbox payments. **Accept:** exact invariant assertions, no unexpected 500s, one entitlement, unchanged completed scores, audit rollback, and a recorded schema ledger/backup. No production data or real charge.
5. **Medium — supported proctoring still needs a false-positive/capability pass (code-confirmed wording, unverified devices).** `QuizTakePage` still claims system overlays/other applications are recorded; those are not universally observable. Camera permission dialogs can produce focus signals; there is no mock detector/browser-transition regression suite. **Task:** correct claims and suppress/deduplicate the app's own permission/dialog episodes; test loading/no-face/away/denied/error, supported fullscreen/visibility/focus/PiP. **Accept:** no green without recent confident detection, no proven cheating event from loading/permission failure, one event per sustained episode, and documented real-camera tests. External OS/Meet capture while focused remains **unsupported**. Firm external-capture requirements need a separately assessed managed extension/native or managed-device integration, with explicit consent/privacy/security design—not a hidden recording feature.
6. **Medium — some required-data reads still turn errors into empty/zero (code-confirmed).** `getTeacherSubmissions` omits error checks on several queries; several `analyticsService` catch blocks return empty arrays or initialized totals. A retry UI cannot help if the API pretends failure is an empty success. **Task:** narrow follow-up per consumer, propagate safe retryable failures and test DB errors vs true zero/empty. **Accept:** authorized empty data is truthful, query failure is visible, no sample/fabricated recovery and no cross-teacher data leak.
7. **Medium — operational security evidence incomplete.** HTTP cookie/token redaction tests pass, but this is not an exhaustive service-log or Git-history secret scan. Production environment validation, key rotation, backups/restore, alert routing and paired API/UI/schema rollback have no deployed evidence. **Task:** read-only staging/config review followed by an isolated restore/rollback drill. **Accept:** secret values never printed, browser bundle has no service key, real restore verified, health failure alerts reach an owner, and release/rollback commit/config/schema versions are recorded.
